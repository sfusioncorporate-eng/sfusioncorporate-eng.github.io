# Дзен: один автоматический выпуск

## Доступ и назначение
Репозиторий: sfusioncorporate-eng/sfusioncorporate-eng.github.io, ветка main.
Сайт: https://sfusioncorporate-eng.github.io/
RSS: https://sfusioncorporate-eng.github.io/rss.xml
Единственный канал назначения: https://dzen.ru/id/68a7478389764b0a8542426d
Часовой пояс: America/Sao_Paulo. Два окна подготовки: около 09:00 и 18:00.
Владелец разрешил автоматическую подготовку и публикацию 20 октября 2026. Повторное одобрение каждой статьи не нужно. Другие заводы не менять. Telegram для доставки полных статей не используется.

## Выполнение
1. Получить свежий main через подключённый GitHub. Рабочие файлы могут исчезать между запусками, источник истины — репозиторий. Прочитать EDITORIAL.md, этот файл, три исходных JSON и content/scheduled-articles.json. Не использовать старый checkout без проверки HEAD.
2. Определить слот по текущему местному времени: до 15:00 — morning, после — evening. slot_id = YYYY-MM-DD-morning или YYYY-MM-DD-evening. До начала затратной работы проверить наличие slot_id в scheduled-articles.json. При существующем выпуске продолжить проверку его размещения, не создавать новую статью. Не догонять пропущенные дни массовой публикацией.
3. Выбрать новую тему о Бразилии с реальной практической пользой, исключить смысловые повторы архива. Проверить источники для изменчивых и специфичных утверждений. Сохранить ссылки, дату проверки и редакторскую оценку в metadata статьи. Не выдумывать личный опыт. Следовать EDITORIAL.md, ориентир не ниже 85/100; исправлять слабые пункты, а не повышать число без правок.
4. Подготовить полную статью на русском: заголовок с географией, описание, ровно четыре смысловых блока с конкретными подзаголовками, 4000–6500 знаков без искусственного растягивания. Одна естественная ссылка на https://www.instagram.com/geonevazhno/ в конце, с честным объяснением содержания. Не обещать отсутствующие материалы. Не вставлять автоматическую фразу об ИИ.
5. Через доступный image_gen создать четыре ОТДЕЛЬНЫЕ фотореалистичные иллюстрации 16:9. Одна генерация — один сюжет. Никаких коллажей/сеток/contact sheet даже для проверки. Посмотреть каждую отдельно, исправить артефакты и несоответствия. Не выдавать вымышленные виды за точные адреса/достопримечательности. При отсутствии инструмента остановить выпуск и сообщить причину; не заменять изображение пустым блоком.
6. Подготовить четыре JPEG минимум 700 px по короткой стороне, предпочтительно около 1600×900, со стабильными уникальными именами assets/articles/<slug>-1.jpg ... -4.jpg. Сохранять исходное соотношение сторон; программное преобразование формата допустимо, создание заменителя фото программой — нет.
7. Добавить одну запись в content/scheduled-articles.json. Схема как у исходных статей: slug, title, description, section, blocks[heading,image (имя без .jpg),alt,paragraphs], cta{text,url,label}. Дополнительные поля slot_id, sources (реальные URL), checked_at, editorial_score и image_prompts. Slug неизменный, нижний ASCII. В content/publication-dates.json добавить реальное UTC время выпуска; не менять даты старых публикаций. JSON допускает обычный текст, HTML в paragraphs будет экранирован.
8. Выполнить python build.py, затем python validate.py (Pillow и lxml). Проверить, что увеличилось число статей ровно на одну, все четыре новых JPEG уникальны и загружаются, полный текст совпадает с RSS, все старые GUID/pubDate неизменны. Изображения находятся после соответствующих подзаголовков. Первоначальные статьи не удалять.
9. Перед коммитом повторно прочитать HEAD. При изменении main перечитать свежие источники, проверить slot_id и объединить свою новую запись без потери чужих изменений. Через GitHub create_blob/create_tree/create_commit/update_ref опубликовать один атомарный коммит с четырьмя JPEG, JSON, generated HTML, index.html, rss.xml, sitemap.xml, статистикой и отчётом. Использовать expected_sha и force=false. Секреты не требуются. Не печатать base64: получать его в память через exec_command, передавать непосредственно create_blob и проверять SHA. Текстовые файлы читать по отдельности, чтобы не получить обрезанный JSON.
10. Проверить Pages workflow и публичные URL новой статьи, четырёх изображений и RSS. Допустимо выполнить validate.py --live; ожидания короткими интервалами. Если обновление не дошло, проверить состояние деплоя и исправить причину; не создавать новую статью для повтора. При неоднозначном результате сначала сверить HEAD, slot_id и публичный RSS.
11. В конце дать короткий отчёт в текущем чате: заголовок, URL сайта, четыре изображения, результат самопроверки, статус Pages/RSS. Статус Дзена отдельный: подтверждён только при прямом доказательстве импорта; иначе «Передано в RSS, импорт Дзена пока не подтверждён». Не обходить блокировки доступа к Дзену и не объявлять его проверенным по одному успешному коммиту. Не отправлять сторонних сообщений и не создавать дополнительные задания.

## Ограничения
Работа по расписанию ещё должна подтвердиться первым реальным автоматическим выпуском. Нет гарантии точного времени импорта или просмотров. Автоматический сбор аналитики Дзена не настроен. При недоступном инструменте/доступе сообщить конкретный блокер; не скрывать пропуск и не отключать расписание самостоятельно.
